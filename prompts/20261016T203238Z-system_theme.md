Implement a system-driven light/dark theme for the existing Mini-Trello application.

First, inspect the repository's `AGENTS.md`, available agent skills, and current implementation. Follow the existing workflow and conventions, and save this starting prompt in `prompts/` using the repository's required filename format.

## Requirements

1. **System-driven default:** On page load, use the operating system's current color-scheme preference to select light or dark mode.
2. **Header toggle:** Add an accessible theme toggle to the existing Header that switches the theme immediately.
3. **Follow system changes:** While the user has not manually changed the theme, automatically update the app whenever the operating system's color-scheme preference changes.
4. **Temporary manual override:** After the user manually toggles the theme, keep their chosen theme for the remainder of the current page session, even if the operating system preference changes.
5. **Reset on reload:** Do not persist the manual choice in local storage, session storage, cookies, or other persistent storage. After a reload, return to the operating system's current preference.
6. **Preserve functionality:** Both `/` and `/board` must remain usable and readable in both themes. Preserve all existing Mini-Trello behavior and interactions.

## Implementation
Use the existing architecture, styling approach, and available skills. Keep the change focused and avoid unnecessary dependencies or unrelated refactoring. Ensure the theme applies consistently to the Header, page backgrounds, text, columns, cards, buttons, borders, and other visible elements.
