# wuchale for i18n, with French as the Source Locale

The interface is internationalised with **wuchale**, a compile-time tool that extracts Messages from naturally-authored JSX and compiles them into per-Locale Catalogs of index-based lookups; the Source Locale is **French**, kept verbatim, and the app ships `fr`, `en`, and `es` with a runtime Header switcher persisted in `localStorage`. We chose wuchale over Lingui and react-i18next because it needs no key namespace or code changes — authors keep writing plain markup — and its compilation yields the smallest bundles; French stays the Source Locale because the app already reads in French, so re-authoring in English would have churned every component and every existing French-asserting test for no user benefit. The costs, knowingly accepted, are a compile-time step and generated loader/proxy files to understand, English and Spanish initially drafted by AI through OpenRouter and left flagged for human review, and a deliberate inconsistency with ADR 0001 — the Active Locale is persisted while the color-mode preference is not, because a language choice is an explicit long-lived preference whereas an appearance override is not.
