# Card collections are read from the board query and written with partial PATCH

A Card's Assignees, Comments, and Checklist Items are not fetched per card: `CardData` carries all three arrays, `useBoard` (`GET /boards/:id`) is their single client source, and `PATCH /cards/:cardId` writes the returned Card back into that cache. We chose this because the API exposes no `GET /cards/:id` — the only way to read a card is as part of its board — so a per-card query would be fiction and a second cache to keep consistent. The cost, knowingly accepted, is that a Card Detail depends on the board payload being current and that the PATCH contract's omit-to-leave-unchanged rule is what keeps the untouched collections safe; the alternative, re-fetching the whole board to refresh one card, was rejected as heavier than writing the single returned Card through.
